# Crew Calendar Preview

Kiro Crew용 캘린더입니다. 달력과 AI 예약 표시는 샘플이며, 대화에서 받은 초안과 일정 제안 설정은 실제로 로컬에 보관합니다. 외부 캘린더 등록·알림·cron 실행은 아직 지원하지 않습니다.

## 시작하기

Node.js 22.18 이상과 실행 중인 Kiro Crew가 필요합니다.

```sh
npm --prefix ui ci --ignore-scripts
npm test
npm run package
```

`npm run package`는 타입 검사·빌드 후 설치용 파일을 `.build/crew-calendar/`에 모읍니다.

처음 설치할 때:

```sh
kirocrew app install "$PWD/.build/crew-calendar"
kirocrew app enable crew-calendar
```

Kiro 사이드바의 **Calendar Preview**에서 엽니다. 앱 경로는 `/apps/crew-calendar`입니다. 이미 설치된 앱에는 Kiro의 업데이트 기능을 사용하고 소스로 `.build/crew-calendar/`를 지정합니다. `app install`은 기존 앱을 덮어쓰지 않습니다.

프로젝트 루트에서 직접 설치하지 않습니다. Kiro 설치기는 Git 제외 규칙을 읽지 않으므로 반드시 실행 파일만 모은 패키지를 사용합니다.

## 구조

```text
app.json                    Kiro 앱 메타데이터·권한
scripts/package.mjs         실행 파일만 담는 패키징
ui/assets/                  실제 앱 아이콘
ui/src/App.tsx              Kiro 진입점·프리뷰 조립
ui/src/calendar/            달력 화면·표시용 타입·시간/배치 계산
ui/src/preview/             샘플 데이터·상태 전환
ui/src/platform/kiro/       호스트 아이콘 호환·SDK 타입
```

`calendar/`는 샘플 목록을 직접 불러오지 않습니다. 화면은 항목과 기준 시각을 전달받고, 시간 계산에도 기준 시각을 명시적으로 전달합니다. 현재 타입은 한 주 안에서 사용하는 표시 모델이며, 실제 공급자 API의 계약은 아닙니다.

Kiro가 React와 SDK를 제공하므로 별도 `main.tsx`나 웹 서버 없이 기본 React export를 ESM으로 빌드합니다. CSS는 `?inline`으로 번들에 포함하고 `.cc-calendar` 범위 안에서만 적용됩니다.

## 명령

- `npm run build`: TypeScript 검사와 UI 빌드
- `npm test`: 날짜·배치 계산 및 패키징 경계 검증
- `npm run package`: 빌드 후 설치용 패키지 생성
- `kirocrew app disable crew-calendar`: 로컬 앱 비활성화

패키지에는 `app.json`, `ui/dist/`, `ui/assets/`, `backend/*.py`가 포함됩니다. 샘플 데이터는 화면 실행에 필요하므로 JS 번들에 포함됩니다. 개발 문서, 소스 원문, 스크린샷, 의존성 폴더는 패키지에 포함하지 않습니다.

## 프리뷰 범위

주간·월간·연간 기간과 달력·목록 전환, 날짜 이동, 레이어 필터, 항목 상세, 샘플 결과물과 빈/부분 오류 상태를 제공합니다. 실제 연결이 필요한 버튼은 비활성화되어 있습니다. 샘플 주는 2026년 9월 28일–10월 4일이며 기준 시각은 수요일 11:40 KST로 고정되어 있습니다. 실제 현재 시각이나 시간대 연동으로 간주하지 않습니다.

선택한 Calendar Spark 아이콘은 `ui/assets/calendar-spark.svg`에 있습니다. 공개 레지스트리 배포와 외부 캘린더 연결은 아직 하지 않았습니다.

## 통합 화면

기본 화면은 두 줄 헤더와 캘린더이며, 일정 상세에서 대화·결과로 직접 접근하는 UI를 제공합니다. 샘플 일정의 대화 버튼은 예시이고, 설정의 실제 초안 목록에서는 원래 Crew 대화로 돌아갈 수 있습니다. AI 작업 자동 예약은 설정의 추가 기능에서 보는 샘플입니다.

자동 예약 ON/OFF, 개별 시간 변경·취소·다시 예약, 예정된 자동 예약 일시정지는 메모리 내 샘플 상태만 변경합니다. OFF는 신규 자동 생성 설정만 끄고 기존 예약은 남겨둡니다. 재로딩하면 기본 샘플로 돌아가며, 외부 API나 저장소를 사용하지 않습니다.

## 샘플 사용자 흐름

- 상단 `추가`에서 내 일정 또는 Crew 작업 예약을 작성합니다. 날짜·시간·종일 여부·반복·관련 일정을 입력하고, 저장 후 해당 주의 항목을 확인합니다.
- 상세의 `편집 · 샘플`에서 수정·삭제할 수 있습니다. 삭제 안내의 `되돌리기`로 복원합니다. 작성 중 닫기는 입력 폐기 여부를 확인합니다.
- 작업 반복은 없음/매일/매주를 지원하는 표시용 샘플입니다. 편집은 전체 예약에 적용됩니다. 실제 스케줄러는 실행하지 않습니다.
- 돋보기로 표시 중인 주의 제목·설명·출처·상태를 검색합니다.
- 설정에서 출처 선택 → 연결 안내 → 캘린더 선택을 미리 봅니다. 실패·재시도·해제·되돌리기도 로컬 상태로만 동작합니다.
- 설정의 화면 미리보기에서 빈 화면, 로딩, 전체 실패, 일부 오류를 선택할 수 있습니다.

일정은 현재 하루 안의 시간 블록 또는 종일 일정으로 작성합니다. 여러 날 일정과 실제 공급자 동기화는 아직 지원하지 않습니다. 새로고침하면 입력한 샘플과 연결 선택은 초기화됩니다.


## 대화 중 일정 제안

- `create_schedule_draft`: 사용자가 명시적으로 요청한 초안을 저장합니다.
- `propose_schedule_draft`: ON인 선택 대화에서 자동 후보를 저장합니다. OFF·알 수 없는 출처·비공개 세션·중복·빈도 제한을 확인합니다.
- 설정은 `data/settings.json`, 초안은 `data/drafts/`에 저장합니다. 샘플 달력과 달리 새로고침해도 유지됩니다.
- 앱 설정에서 적용할 일반 대화를 선택합니다. 초깃값은 OFF입니다. 임시·비공개 대화와 서브에이전트에는 적용하지 않습니다.
- Crew의 에이전트 기능 → 훅에서 `UserPromptSubmit` 훅을 한 번 연결합니다. 앱 설정의 ‘처음 한 번 연결하기’에 현재 설치 위치에 맞는 정확한 명령이 있습니다. 이름은 `Crew Calendar · schedule suggestions`, 매처는 비워두고 제한 시간은 5초를 권장합니다. 훅 등록은 Crew 소유자 절차로 수행하며 앱은 전역 훅 설정을 덮어쓰지 않습니다.
- 훅 연결 후 설정 다시 확인을 누르면 토글을 사용할 수 있습니다. OFF 지침은 다음 사용자 메시지부터 반영되고, 자동 저장은 서버에서 최신 설정을 다시 확인합니다. 이미 생성 중인 자연어 답변을 소급 취소하지 않습니다.
- 앱을 제거할 때는 Crew에서 이 훅도 비활성화·삭제하세요. 앱 비활성화 중에는 ON 지침을 전달하지 않습니다.
- 같은 대화의 자동 후보는 30분 간격으로 제한합니다. 직접 요청에는 이 제한이 없습니다. 같은 행동·마감의 후보를 넘긴 뒤 준비 시각만 바꿔 다시 제안하지 않습니다. 다른 마감의 다음 회차는 허용하며, 마감을 모르면 추천 날짜를 회차 기준으로 사용합니다.
- 별도 분석 모델은 호출하지 않지만 지침과 도구 응답은 토큰을 사용합니다. OFF를 비용 0으로 보장하지 않습니다. 수동 도구의 ‘명시적 요청’ 판단은 모델 지침이며 사용자 의도를 서버가 독립적으로 증명하는 권한 체계는 아닙니다.

`npm test`로 UI 계산·패키징·Python 저장/훅/API 테스트를 실행합니다. aiohttp가 없는 개발 Python에서는 API 테스트가 skip될 수 있으므로 설치된 Crew Python으로 `-m unittest discover -s tests`도 실행하세요. 앱 업데이트 후 새로운 도구가 검색만 되고 호출되지 않으면 호스트가 앱 MCP 서버를 tools 목록에도 반영했는지 확인합니다. 동작 중인 다른 대화를 임의로 재시작하지 않습니다.


## 아키텍처 경계

- `backend/domain.py`: 입력과 초안 값. 파일·Crew API를 알지 않습니다.
- `backend/proposal_policy.py`: 중복·마감 회차·빈도·허용 상태 규칙.
- `backend/application.py`, `settings.py`, `hook_context.py`: 초안·설정·메시지 지침의 독립된 사용 사례.
- `backend/repository.py`: 저장 계약과 현재 JSON 구현. 설정 변경과 자동 생성에 공통 트랜잭션을 제공합니다.
- `backend/host.py`: Crew 대화 식별·대화 목록·훅·원래 대화 경로를 모은 호스트 어댑터.
- `backend/composition.py`: 실제 JSON 저장소와 사용 사례를 연결하는 한 곳.
- `backend/routes.py`, `mcp_server.py`, `proposal_hook.py`: HTTP·MCP·훅 입출력만 담당하는 진입점.
- `backend/drafts.py`: 기존 v0.1 Python 호출과 테스트를 위한 얇은 호환 계층. 새로운 규칙을 넣지 않습니다.

게이트웨이는 Crew가 제공하는 앱별 Python 패키지와 재로딩을 그대로 사용합니다. 별도 MCP/훅 프로세스의 `runtime.py`는 로컬 패키지 부트스트랩만 맡습니다.

저장 계약은 JSON/메모리 구현에서 동일하게 검사하며 기존 파일을 덮어쓰는 마이그레이션은 없습니다. DB 교체 시에는 같은 잠금·개별 쓰기 원자성·오류·정렬 계약을 구현해야 합니다. 현재 transaction은 배타 구간이며 여러 쓰기의 롤백 보장은 아닙니다. JSON 구현은 아직 세션별 조회 시 전체 파일을 읽으므로 대량 데이터 처리용으로 검증된 것은 아닙니다.

외부 캘린더의 확정 일정은 초안과 별도 개념입니다. 공급자를 추가할 때는 공급자 어댑터와 명시적인 확정/동기화 사용 사례를 추가하고, 초안 ID를 외부 일정 ID로 재사용하지 않습니다. 공급자·계정·캘린더·이벤트·반복 회차 식별과 외부 저장 성공 증거를 별도로 관리해야 합니다. 현재 외부 공급자 인터페이스나 쓰기 기능을 구현했다는 뜻은 아닙니다.
